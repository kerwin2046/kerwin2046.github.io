> 写对主逻辑只完成了一半；另一半是：在极端输入、临界状态和不变量失效处，程序仍然行为正确、定义清晰、不会悄悄出错。

## 一、为什么「边界」值得单独成篇

很多人把边界理解成「多测几个 corner case」。这太窄了。

在竞赛和面试里，边界失误表现为：RE（越界、栈溢出）、WA（漏解、多解、比较错）、TLE（退出条件写错导致死循环）。在工程里，边界失误往往更隐蔽：返回了「看起来合理」的错误结果，或者只在特定数据规模下才暴露。

**边界不是测试技巧，而是你对问题定义理解深度的外显。**

同一份代码：

- 主路径体现「一般情况怎么做」；
- 边界处理体现「问题的定义在端点处是什么」。

因此，全面考虑边界 = **在写代码之前，就把问题的数学/逻辑端点想清楚**；测试只是验证，不是发现的唯一手段。

## 二、先建立坐标系：三类边界

把所有「特殊情况」放进三个维度，避免遗漏时脑子里一团乱。

| 维度 | 核心问题 | 典型场景 |
|------|----------|----------|
| **输入边界** | 合法输入长什么样？极端形态是什么？ | 空、单元素、全相同、已排序/逆序、值域极值 |
| **状态边界** | 算法执行到某一步时，内部表示有何特殊？ | 头尾指针、空栈、环入口、递归到底、窗口长度为 0 |
| **不变量边界** | 循环/递归依赖的「恒真条件」何时成立/失效？ | `left > right` 仍迭代、区间长度为 0 仍转移、标记未回溯 |

### 2.1 输入边界：数据的形状

关注 **规模**（`n`）、**值**（大小、符号、重复）、**结构**（顺序、连通性）。

口诀：**空、一、二、极、重、序**

- **空**：零长度、空指针、空集
- **一**：单元素、单节点、单连通分量
- **二**：两元素（很多 off-by-one 在 `n=2` 才出现）
- **极**：最小/最大 `n`、值域边界、溢出
- **重**：重复键、重复边、全相同
- **序**：有序、逆序、几乎有序、随机

### 2.2 状态边界：算法内部的「快照」

同一输入，不同算法在中间态不同。例如反转链表：

- 输入边界：`head == null`、单节点
- 状态边界：最后一次迭代时 `prev`/`curr`/`next` 谁指向谁；返回的是原头还是新头

**状态边界往往比输入边界更难**，因为它要求你能 **手推 2～3 轮循环**，而不是只盯着输入输出。

### 2.3 不变量边界：正确性的脊梁

循环和递归几乎总依赖某种不变量（loop invariant）：

> 每一轮迭代开始前，条件 P 成立；迭代体执行后 P 仍成立；退出循环时 P 加上退出条件可推出答案。

边界 bug 的高发区：

1. **进入循环前** P 不成立（初始化错）
2. **退出后** 用 P 推不出答案（退出条件与 P 不匹配）
3. **端点轮** 最后一次迭代破坏 P（少做/多做一轮）

**二分查找**是教科书级例子：`while (left <= right)` 与 `while (left < right)` 对应不同的不变量与答案位置，混用必 WA。

## 三、用「契约」把边界从直觉变成义务

实现任何函数前，用三行约束自己（可写在草稿纸或注释里）：

```text
前置条件（Precondition）：调用方保证什么？（竞赛题常假设输入合法）
后置条件（Postcondition）：必须返回什么？多解时返回哪一个？
不变量（Invariant）：循环/递归每一时刻什么为真？
```

然后对每一行追问：

| 追问 | 目的 |
|------|------|
| 前置条件被违反时我会怎样？ | 区分「题目保证」与「自己要防御」 |
| 后置条件在 `n=0` 时仍成立吗？ | 挖输入边界 |
| 不变量在第一轮、最后一轮成立吗？ | 挖状态与退出边界 |

**深度点**：很多「边界」其实是 **后置条件在端点未定义**。例如「返回第 k 小」——`k > n` 时返回什么？题目没说就要澄清或按惯例处理。

## 四、四个思维工具（比背清单更重要）

### 4.1 对称性

处理了左端点，是否同等处理了右端点？处理了头节点，是否处理了尾节点？双指针、二分、分治都适用。

自问：**若输入左右翻转，我的代码是否仍正确？** 若否，可能漏了对称边界。

### 4.2 单调性

若性质随下标/时间单调，答案常在 **第一个破坏性质的位置**。这与二分边界、滑动窗口右扩停止条件同源。

自问：**我是在「找第一个不满足」还是「找最后一个满足」？** 两种写法缩区间方向相反。

### 4.3 反例构造（主动找茬）

写完贪心或直觉解法后，不要先庆祝，先问：

- 两个相等元素交换顺序会怎样？
- 全相同、锯齿形、只有一头一尾特殊？
- 是否存在「局部最优 ≠ 全局最优」的极小输入？

LeetCode 上许多高赞 WA 讨论，本质都是 **极小反例**。

### 4.4 维度扫描（系统化查漏）

按固定顺序扫，而不是随机想到一个测一个：

```text
1. 规模维：n = 0, 1, 2, 最大
2. 值域维：min, max, 0, 负, 重复
3. 结构维：顺序、退化结构（链状树、单点图）
4. 范式维：你的算法类型（二分/DP/图）的特有坑
5. 实现维：溢出、下标、闭开区间、是否修改输入
```

## 五、按数据结构：专属边界地图

通用口诀解决不了的，由结构决定。

### 5.1 数组 / 字符串

- 下标：`0`、`n-1`、`i±1` 是否越界
- 子区间：空区间、整段、单点
- 双指针：相遇、交叉、一方先到头
- 前缀和：空前缀、`[0,0]` 是否参与累加

### 5.2 链表

- `null` 头、单节点、尾 `next`
- 虚拟头结点：简化删头，但别忘记返回 `dummy->next`
- 快慢指针：无环、有环、环长为 1
- 原地修改：断链后是否丢引用、是否形成环

### 5.3 栈 / 队列 / 单调栈

- 空栈 `pop` / `top`
- 相等元素：弹栈时 `<` 还是 `<=`
- BFS 队列：起点即终点、层数为 0

### 5.4 树

- 空树、仅根、仅左/仅右
- BST：重复键、退化成链
- 递归：深度、`null` 返回值语义（0 还是 -1？）
- 迭代：显式栈/队列为空时的处理

### 5.5 图

- 无点、无边、自环、重边、不连通
- 有向 / 无向、权为 0、负权（最短路）
- 访问标记：何时入队、何时标记、回溯是否清标记

### 5.6 哈希 / 堆

- 哈希：大量冲突、key 不存在、删除后再查
- 堆：空堆取顶、大量相同 priority、懒删除是否一致

## 六、按算法范式：第二层边界

### 6.1 二分

- 循环条件：`<=` vs `<` 与答案落在左半/右半的关系
- 中点：`mid = left + (right - left) / 2` 防溢出
- 语义：找第一个 `>= x` vs 最后一个 `<= x`，缩右还是缩左
- 无解：全 `false` / 全 `true` 时返回值

### 6.2 滑动窗口

- 窗口为空、覆盖全串
- 扩张停止条件 vs 收缩停止条件
- 「最长」与「最短」窗口更新时机不同

### 6.3 DFS / BFS / 回溯

- 起点 = 终点
- 回溯：撤销状态是否完整（图染色、排列 visited）
- 记忆化：状态键是否漏维度

### 6.4 动态规划

- 初始化：第 0 行/列、空集、不可能状态用何值（`0` / `INF` / `-1`）
- 转移：依赖范围是否越界
- 滚动数组：当前行/列下标映射
- 答案位置：`dp[n]` 还是 `dp[n-1]`，与题意索引对齐

### 6.5 贪心

- 排序关键字是否完整（tie-break）
- 证明不了时，用反例驱动而不是加 if

## 七、从写到交：可执行工作流

```text
读题 → 形式化（输入、输出、约束）
     → 手推 n=0,1,2 与一个「正常」样例
     → 写契约（前置/后置/不变量）
     → 实现主路径
     → 按「空一二极重序 + 结构 + 范式」列测试
     → 手推测试（尤其最后一轮循环）
     → 提交；若 WA，按根因分类（见下节）而非乱改
```

**建议**：维护个人「边界错题本」，每条记录：题型、漏掉的边界类型、极小反例。30 天计划里每天加 2～3 条，一个月后比任何通用清单都值钱。

## 八、WA / RE 之后的根因分类（避免盲目改）

| 现象 | 优先怀疑 |
|------|----------|
| RE | 越界、空指针、递归过深、除零 |
| TLE | 死循环、退出条件、复杂度估错 |
| WA 小数据对、大数据错 | 溢出、未取模、比较器错误 |
| WA 全错 | 题意理解、方向反了、索引体系混乱 |
| WA 部分对 | 典型边界：相等元素、端点、多解、闭开区间 |

改代码前先用 **最小反例** 手推一遍，确认属于哪一类，再动刀。

## 九、边界测试 vs 正确性证明

二者互补，不可替代。

- **边界测试**：低成本验证端点行为，适合竞赛快速迭代。
- **不变量 / 归纳证明**：保证一般 `n` 正确，避免「测了十个点仍漏掉一类结构」。

深度实践：**主路径用证明想清楚，端点用清单扫一遍，最后用极小反例验证怀疑。**

## 十、一页纸自检清单（可打印）

```text
□ 规模：0, 1, 2, max
□ 值域：min, max, 0, 负, 重复
□ 顺序：升序, 降序, 随机
□ 结构退化：链、单点、不连通
□ 下标/指针：头, 尾, i±1, 空
□ 循环：进入前/最后一轮/退出后 不变量成立？
□ 区间：闭还是开？空区间算不算？
□ 溢出与类型：int → long long？取模？
□ 多解/无解：题目要求？
□ 对称性：翻转/镜像输入仍对吗？
```

## 十一、结语：边界是问题定义的一部分

全面考虑边界，不是考前的迷信，而是 **把算法的定义写完整** 的习惯：

1. 用 **三类边界** 建坐标系（输入 / 状态 / 不变量）；
2. 用 **契约** 固定前置、后置与不变量；
3. 用 **对称、单调、反例、维度扫描** 主动发现漏洞；
4. 用 **结构 + 范式** 清单补专业坑；
5. 用 **工作流 + 错题本** 把经验沉淀下来。

当你能在纸上用三句话说明「`n=0` 时为什么返回这个值」「循环最后一轮为什么仍满足不变量」时，边界就已经被你想清楚了；代码只是把答案写下来而已。

## 附录：与每日练习的衔接

| 练习日 | 建议重点边界 |
|--------|----------------|
| 数组 / 双指针 | 空、单元素、全相同、两指针同位 |
| 链表 | `null`、单节点、删头尾、断链 |
| 二分 | 空数组、单元素、全满足/全不满足、`left==right` |
| 树 | 空树、单链、返回值语义 |
| 图 | 不连通、自环、起点=终点 |

做链表题（如反转链表、合并有序链表）时，可优先对照 **5.2 链表** 与 **手推最后一轮迭代** 两项。
